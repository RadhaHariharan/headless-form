# useForm

**File:** `src/hooks/use-form.ts`

The primary hook — bridges the framework-agnostic store from [`@headlesskit/forms`](../../forms/store/01-create-form-store) to React's rendering model via `useSyncExternalStore`. The exact same hook works unchanged for React Native through `@headlesskit/forms-react-native`, which re-exports it directly.

## Signature

```typescript
function useForm<Values = Record<string, unknown>, TransformedValues = Values, TError = ReactNode>(
  options?: UseFormOptions<Values, TransformedValues, TError>,
): UseFormReturnType<Values, TransformedValues, TError>
```

Accepts the exact same `UseFormOptions` as [createFormStore](../../forms/store/01-create-form-store) — see that doc and [store.types](../../forms/types/01-store-types) for the full options table. Two React-specific defaults differ from core:

| | Core (`createFormStore`) default | `useForm` default |
|---|---|---|
| `mode` | `'controlled'` | **`'uncontrolled'`** — best performance is the recommended default for React. |
| `TError` | `unknown` | **`ReactNode`** — lets you return JSX directly as an error value (e.g. `<span className="hint">Required</span>`). |

## How it actually works

```typescript
const storeRef = useRef<FormStoreApi<Values, TransformedValues, TError> | null>(null);
if (storeRef.current === null) {
  storeRef.current = createFormStore<Values, TransformedValues, TError>({
    mode: 'uncontrolled',
    ...options,
  });
}
const store = storeRef.current;
```

The store is created **exactly once** per component instance (the classic `useRef` lazy-init pattern — not `useState`, since there's no need to ever trigger a re-render from *changing* the ref itself) and never recreated across re-renders, regardless of how `options` changes between renders. This means: **`options` is only read on the very first render** — passing a new `initialValues` object on a later render has no effect on the already-created store. If you need to react to changing options later, use the form's own imperative methods (`setValues`, `setInitialValues`, etc.) rather than expecting prop changes to flow through automatically.

```typescript
const snapshot = useSyncExternalStore(
  useCallback((onStoreChange) => store.subscribe(onStoreChange), [store]),
  () => store.getSnapshot(),
  () => store.getServerSnapshot(),
);
```

This is the entire React-reactivity bridge: `useSyncExternalStore` re-renders the component whenever `store.subscribe`'s callback fires (i.e. whenever [createFormStore](../../forms/store/01-create-form-store)'s `notifySubscribers()` runs) and reads the current `snapshot` (errors/touched/dirty/validating/submitting/etc — see [FormStoreSnapshot](../../forms/types/01-store-types)) on every render. The `getServerSnapshot` argument makes this hook safe to call during SSR/RSC rendering, where `getSnapshot`/`getServerSnapshot` must return the same stable reference (the underlying store guarantees this — see [createFormStore](../../forms/store/01-create-form-store)'s subscription contract).

## The returned object is a snapshot/store hybrid, not the store itself

```typescript
return {
  ...store,
  errors: snapshot.errors,
  validating: snapshot.validating,
  submitting: snapshot.submitting,
  initialized: snapshot.initialized,
  get values() { return store.getValues(); },
  setFieldValue: store.setFieldValue.bind(store),
  // ...every other method bound to `store`
  key: (path) => `${snapshot.formKey}-${path}-${snapshot.fieldKeys[path] ?? 0}`,
  // ...
};
```

Every render builds a **fresh plain object**, but:
- **Reactive fields** (`errors`, `validating`, `submitting`, `initialized`) are read straight from the current `snapshot` — these are exactly the fields that change identity/value when `useSyncExternalStore` triggers a re-render, so reading them from `snapshot` (rather than calling a store getter) ensures the returned object's values are consistent with *this specific render*.
- **`values`** is a getter that calls `store.getValues()` live — **not** snapshot-derived, since values are deliberately excluded from the observable snapshot (see [createFormStore](../../forms/store/01-create-form-store)). In uncontrolled mode this means `form.values` read during render reflects the latest *committed* value, but reading it doesn't subscribe you to future value changes the way reading `form.errors` does.
- **Every mutating/query method** (`setFieldValue`, `validate`, `getInputProps`, etc.) is just `store.<method>.bind(store)` — a stable reference to the underlying store's own implementation, doing no extra work in the React layer.
- **`key(path)`** is the one method *not* delegated directly — it's reimplemented inline, reading `formKey`/`fieldKeys` from the **current snapshot** rather than calling `store.key()` (which reads the store's live internal state directly). This matters because `key()`'s whole purpose is to drive a React `key` prop, which only causes a remount when its *returned string* changes between renders — reading from the snapshot guarantees the string is computed consistently with the render that's currently happening, in lock-step with `useSyncExternalStore`'s contract.

## `UseFormReturnType<Values, TransformedValues, TError>`

```typescript
type UseFormReturnType<Values, TransformedValues = Values, TError = ReactNode> =
  Omit<FormStoreApi<Values, TransformedValues, TError>, 'onSubmit'> & {
    onSubmit(
      onValid: (values: TransformedValues, event: FormEvent<HTMLFormElement> | undefined) => void | Promise<void>,
      onInvalid?: (errors: FormErrors<TError>, values: Values, event: FormEvent<HTMLFormElement> | undefined) => void,
    ): FormEventHandler<HTMLFormElement>;
  };
```

Identical to [FormStoreApi](../../forms/types/01-store-types) except `onSubmit` is re-typed for React specifically: the returned handler is a `FormEventHandler<HTMLFormElement>` (React's exact event-handler type for `<form onSubmit>`), and the callbacks receive React's synthetic `FormEvent` rather than the generic DOM `Event` core's type declares — at runtime this is the same object React actually passes, just typed precisely for React consumers.

## Basic usage

```tsx
import { useForm } from '@headlesskit/forms-react';

const form = useForm({
  mode: 'uncontrolled',
  initialValues: { name: '', email: '' },
});
```

## Full example

```tsx
import { useForm, isEmail, isNotEmpty, hasLength } from '@headlesskit/forms-react';

interface FormValues {
  name: string;
  email: string;
  password: string;
  age: number;
}

function RegistrationForm() {
  const form = useForm<FormValues>({
    mode: 'uncontrolled',
    initialValues: { name: '', email: '', password: '', age: 18 },
    validate: {
      name: isNotEmpty('Name is required'),
      email: isEmail('Invalid email'),
      password: hasLength({ min: 8 }, 'Password must be at least 8 characters'),
      age: (value) => (value < 18 ? 'Must be 18 or older' : null),
    },
    transformValues: (values) => ({ ...values, name: values.name.trim() }),
  });

  return (
    <form onSubmit={form.onSubmit((values) => console.log(values))}>
      <input key={form.key('name')} {...form.getInputProps('name')} placeholder="Name" />
      {form.errors.name && <p>{form.errors.name}</p>}

      <input key={form.key('email')} {...form.getInputProps('email')} type="email" placeholder="Email" />
      {form.errors.email && <p>{form.errors.email}</p>}

      <button type="submit" disabled={form.submitting}>
        {form.submitting ? 'Submitting...' : 'Register'}
      </button>
    </form>
  );
}
```

## Advanced: reading the form's transformed-values type elsewhere

```typescript
import type { UseFormReturnType, TransformedValues } from '@headlesskit/forms-react';

type MyForm = UseFormReturnType<FormValues, { name: string; email: string; fullName: string }, string>;
type Output = TransformedValues<MyForm>; // { name: string; email: string; fullName: string }
```

## Common pitfalls

- **`options` is only consumed on the first render** — re-rendering a component with `useForm({ initialValues: newValues })` where `newValues` differs from the previous render does **not** update the form; the store was already created. Use `form.setValues(newValues)` or `form.setInitialValues(newValues)` explicitly when you need to react to changed props after mount.
- **Always pair an uncontrolled-mode input with `key={form.key(path)}`** — see [field-keys](../../forms/store/02-field-keys) for why; forgetting it means programmatic `setFieldValue` calls silently fail to update what's displayed.
- **`form.values` is not what re-renders the component in uncontrolled mode** — only `errors`/`touched`/`dirty`/`validating`/`submitting`/`initialized`/the field keys do, since those are the snapshot fields `useSyncExternalStore` actually subscribes to; reading `form.values` inside a render doesn't cause future value changes to re-trigger that render the way reading `form.errors` does.
