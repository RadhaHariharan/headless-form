# Examples

**525 worked examples** across five packages — [`@headlesskit/forms`](../forms/01-overview.mdx) (plus its React bindings), [`@headlesskit/state-management`](../state-management/01-overview.mdx), [`@headlesskit/state-management-simplify`](../state-management-simplify/01-overview.mdx), [`@headlesskit/state-management-toolkit`](../state-management-toolkit/01-overview.mdx), and [`@headlesskit/query-core`](../query-core/01-overview.mdx) — each graduated from **Basic** (25 examples) to **Medium** (30 examples) to **Advanced** (50 examples), with real, copy-pasteable code and an in-depth "How it works" explanation underneath every snippet.

This section is a *recipe book*, not a replacement for the per-file API docs each package already has. When an example uses something non-obvious, it links back to the exact doc page that covers it in full.

Each of those fifteen pages contains exactly the numbered example count in its column header, for **525 total**. **Basic** assumes nothing beyond "I installed the package" — one concept per example. **Medium** combines two or three basic concepts into realistic patterns (cross-field validation, middleware composition, tag-based cache invalidation, persisted state). **Advanced** covers architecture-level concerns: deeply nested/normalized state, full GET/POST/PATCH/PUT/DELETE CRUD suites, classic and infinite pagination, testing in isolation, performance, SSR, time-travel debugging, and how these packages compose with each other (including [`@headlesskit/state-management-devtools`](../state-management-devtools/01-overview.mdx)).

Two groups deserve a callout since they cover request/response and data-fetching concerns most directly:
- **`state-management-toolkit`** bundles an RTK-Query-equivalent (`createApi`/`fetchBaseQuery`) directly into the store — its Advanced examples include a full CRUD suite (GET list, GET by id, POST, PATCH, PUT, DELETE) with tag-based cache invalidation, plus `build.infiniteQuery` for cursor- and page-based infinite pagination.
- **`query-core`** is the lower-level, framework-agnostic primitive (`QueryClient`/`QueryObserver`/`MutationObserver`/`InfiniteQueryObserver`) that a hook-based binding would be built on top of — it has no React hooks of its own, and its examples are explicit about that, showing the observer pattern directly plus one clearly-labeled illustrative hook sketch.

## How to read an example

Every example follows the same shape:

```text
## N. Title — one-line scenario

​```language
code
​```

**How it works:** the mechanism, not just a restatement of the code — what's reactive vs.
not, what re-renders, what the library is doing for you under the hood, and the specific
pitfall this pattern avoids or walks into.
```

Code samples favor TypeScript and React (via `forms-react` / `state-management-simplify-react`) since that's how these packages are used in practice — the underlying vanilla packages (`forms`, `state-management`, `state-management-simplify`) are framework-agnostic, and several Advanced examples in each section show the same pattern with no framework at all.

## Common pitfalls

- **These examples are deliberately self-contained.** Most omit imports for brevity inside a single page (the H2 title and surrounding prose tell you which package each function comes from); copy the actual `import` lines from the linked API docs if you're pasting into a real file.
- **"Basic" doesn't mean "toy."** Every basic example is a real, valid pattern you'd actually ship — basic just means it demonstrates exactly one concept in isolation.
- **Advanced examples assume you've read Basic and Medium first** in the same package — they build on vocabulary (mode, middleware, selectors) introduced earlier rather than re-explaining it.
