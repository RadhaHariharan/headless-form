# createInspectorStore

**File:** `src/create-inspector-store.ts`

Builds the store of every connection's lifted (time-travel-capable) state — the data layer a UI like `Inspector` renders, and the thing `installDevtools` wires into the connector globals.

```typescript
import { createInspectorStore } from '@headlesskit/state-management-devtools';
```

## Signature

```typescript
function createInspectorStore(maxActionsPerConnection?: number): InspectorStoreController

interface InspectorStore {
  getSnapshot(): InspectorSnapshot;
  subscribe(listener: () => void): () => void;
  jumpToState(connectionName: string, index: number): void;
  jumpToAction(connectionName: string, actionId: number): void;
  toggleAction(connectionName: string, actionId: number): void;
  sweep(connectionName: string): void;
  commit(connectionName: string): void;
  reset(connectionName: string): void;
  rollback(connectionName: string): void;
  revert(connectionName: string): void;
  pause(connectionName: string, paused: boolean): void;
  lock(connectionName: string, locked: boolean): void;
  importState(connectionName: string, liftedState: LiftedState): void;
  clear(connectionName?: string): void;
}
```

`InspectorStoreController` additionally exposes `registerConnection` and `setControlListener` — internal hooks used by [`createDevtoolsExtension`](./05-create-devtools-extension.mdx), not typically called directly.

## What each method does

| Method | Effect |
|--------|--------|
| `jumpToState(name, index)` | Moves the viewed index to a specific computed state. `-1` shows the committed baseline. |
| `jumpToAction(name, id)` | Moves the viewed index to the state produced by a specific action id. |
| `toggleAction(name, id)` | Marks an action as skipped (or un-skips it) — skipped actions are excluded from state computation but stay in history until swept. |
| `sweep(name)` | Permanently removes every currently-skipped action. |
| `commit(name)` | Folds the currently viewed state into `committedState` and clears history — like a checkpoint. |
| `reset(name)` | Clears history and recomputes from the connection's *original* initial state (undoes everything, including prior commits). |
| `rollback(name)` | Clears history but keeps the current `committedState` (undoes everything since the last commit). |
| `revert(name)` | Removes only the most recently dispatched action. |
| `pause(name, paused)` | Stops (or resumes) recording new actions — dispatched actions are ignored entirely while paused. |
| `lock(name, locked)` | Stops (or resumes) the viewed index auto-following new actions, so you can inspect history while the app keeps running. |
| `importState(name, liftedState)` | Replaces a connection's lifted state wholesale (e.g. from a file exported earlier). |

Every method above is a no-op if `connectionName` isn't registered (e.g. the UI references a connection that disconnected) — there's no error to catch.

## Basic usage

```typescript
const inspectorStore = createInspectorStore();

inspectorStore.subscribe(() => {
  console.log(inspectorStore.getSnapshot());
});
```

You won't usually call this directly — [`installDevtools`](./02-install-devtools.mdx) does it for you and wires the result into both connector globals.

## Common pitfalls

- **`maxActionsPerConnection` bounds staged actions, not history correctness.** Once a connection exceeds the cap, the *oldest* staged actions are folded into `committedState` (auto-committed) rather than discarded outright — `getEffectiveState` always stays correct, but those folded actions are no longer individually inspectable or revertable.
- **`jumpToState`/`jumpToAction` only move a pointer** — they don't trigger recomputation. Recomputation happens on `toggleAction`, `sweep`, `commit`, `reset`, `rollback`, `revert`, and `importState`, since those are the only commands that change *which* actions feed into `computedStates`.
