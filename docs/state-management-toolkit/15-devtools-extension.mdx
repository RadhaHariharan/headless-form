# devtoolsExtension

**File:** `src/devtoolsExtension.ts`

Integrates with headlesskit's own DevTools connector, if one is installed. [configureStore](./04-configure-store) uses this automatically (`devTools: true` by default) — most apps never import from this file directly.

This file owns the connector types and the ambient `window.__HEADLESSKIT_DEVTOOLS_EXTENSION__`/`window.__HEADLESSKIT_DEVTOOLS_EXTENSION_COMPOSE__` global declarations for this package. [state-management-simplify's devtools middleware](../state-management-simplify/06-middleware-devtools) declares the same globals independently, since each package is built and type-checked on its own.

These globals are **headlesskit's own** — they are not set by, and have no relation to, any third-party browser extension. No connector ships yet (a DevTools UI/connector that populates these globals is planned future work); until one exists, `devTools: true` is a safe no-op.

## `composeWithDevTools(options)`

```typescript
function composeWithDevTools(...funcs: StoreEnhancer[]): StoreEnhancer
function composeWithDevTools(options: DevToolsEnhancerOptions): Compose
```

A drop-in alternative to plain `compose` from `@headlesskit/state-management` that also wires in the DevTools connector's enhancer, **if** `window.__HEADLESSKIT_DEVTOOLS_EXTENSION_COMPOSE__` exists (populated by whatever installs a headlesskit DevTools connector). If nothing has populated it, this silently falls back to plain `compose` — your app behaves identically either way.

## `DevToolsEnhancerOptions` — selected options

| Option | Type | Default | Description |
|--------|------|---------|--------------|
| `name` | `string` | `document.title` | Label shown for this store instance in the DevTools monitor — useful when multiple stores/tabs are open at once. |
| `trace` | `boolean \| (action) => string` | `false` (`configureStore` sets this `true` in development) | Captures a stack trace at the point each action was dispatched, so the DevTools panel can show you *where in your code* an action came from. |
| `traceLimit` | `number` | `10` | Max stack frames recorded per action — higher values cost more memory/performance per dispatch. |
| `actionSanitizer` / `stateSanitizer` | `(value, index) => value` | none | Redact or transform sensitive fields (auth tokens, PII) before they're sent to the DevTools panel — important if DevTools state ever gets shared/screenshotted. |
| `actionsDenylist` / `actionsAllowlist` | `string \| string[]` (regex) | none | Hide noisy, high-frequency action types (e.g. a mouse-position-tracking action) from the monitor's timeline. |
| `maxAge` | `number` | `50` | Maximum action history retained — older entries are dropped, bounding memory usage in long-running sessions. |

## Basic usage (via configureStore — the common path)

```typescript
import { configureStore } from '@headlesskit/state-management-toolkit';

const store = configureStore({
  reducer: rootReducer,
  devTools: {
    name: 'My App',
    trace: true,
    actionsDenylist: ['mouse/moved'],
  },
});
```

## Advanced: redacting sensitive state before it reaches the DevTools connector

```typescript
const store = configureStore({
  reducer: rootReducer,
  devTools: {
    actionSanitizer: (action) =>
      action.type === 'auth/login' ? { ...action, payload: { ...action.payload, password: '<redacted>' } } : action,
    stateSanitizer: (state) => ({ ...state, auth: { ...state.auth, token: '<redacted>' } }),
  },
});
```

## Advanced: calling `composeWithDevTools` directly with plain `createStore`

If you're using plain `@headlesskit/state-management` (not the toolkit's `configureStore`) but still want DevTools support:

```typescript
import { createStore, applyMiddleware } from '@headlesskit/state-management';
import { composeWithDevTools } from '@headlesskit/state-management-toolkit';

const store = createStore(
  rootReducer,
  composeWithDevTools(applyMiddleware(thunkMiddleware)),
);
```

## Common pitfalls

- **`devTools: true` (the default) does nothing until a connector populates `window.__HEADLESSKIT_DEVTOOLS_EXTENSION__`** — it's a no-op fallback, not an error. No connector ships in this package yet; this is wiring for future work, not something you can currently watch in a panel.
- **No other browser extension will connect here.** This package only reads its own `__HEADLESSKIT_DEVTOOLS_EXTENSION__` globals — nothing else populates them.
- **Sanitizers only affect what the DevTools panel *displays***, not what's actually stored in application state — `actionSanitizer`/`stateSanitizer` don't redact your real application state, only the copy shipped to the connector's UI.
